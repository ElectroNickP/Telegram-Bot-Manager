# 🔗 Руководство по пользовательским сессиям

## 📋 Обзор

Система пользовательских сессий позволяет пользователям Telegram бота устанавливать прямую связь друг с другом через бота. Когда между двумя пользователями установлена сессия, все сообщения, отправленные боту, автоматически пересылаются партнеру по сессии.

## ✨ Возможности

- **Установка сессий** между пользователями через команду `/connect`
- **Выбор пользователя** из списка активных пользователей
- **Подтверждение/отклонение** запросов на подключение
- **Автоматическая пересылка** всех типов сообщений (текст, голос, фото, документы)
- **Завершение сессий** через команду `/exit`
- **Безопасность** - только приватные чаты, защита от спама

## 🚀 Как использовать

### 1. Установление сессии

1. Отправьте команду `/connect` боту в личном сообщении
2. Бот покажет список доступных пользователей (которые недавно писали боту)
3. Выберите пользователя из списка, нажав на соответствующую кнопку
4. Запрос будет отправлен выбранному пользователю

### 2. Ответ на запрос сессии

Когда кто-то хочет установить с вами сессию:

1. Вы получите сообщение с кнопками "✅ Принять" и "❌ Отклонить"
2. Нажмите "✅ Принять" для установления сессии
3. Нажмите "❌ Отклонить" для отклонения запроса

### 3. Общение в сессии

После установления сессии:

- Все ваши сообщения боту будут автоматически пересылаться партнеру
- Сообщения партнера будут приходить вам с пометкой отправителя
- Поддерживаются все типы сообщений: текст, голос, фото, документы

### 4. Завершение сессии

Для завершения активной сессии:

1. Отправьте команду `/exit` боту
2. Сессия будет завершена для обеих сторон
3. Партнер получит уведомление о завершении сессии

## 📝 Команды

| Команда | Описание |
|---------|----------|
| `/connect` | Показать список пользователей для подключения |
| `/exit` | Завершить активную сессию |

## ⚙️ Технические детали

### Архитектура

Система сессий построена на современной гексагональной архитектуре:

- **Domain Layer**: `UserSession`, `UserInfo`, `SessionStatus`
- **Use Cases**: `UserSessionManagementUseCase`
- **Services**: `UserSessionService`
- **Storage**: `JsonConfigStorageAdapter`

### Хранение данных

- Сессии сохраняются в JSON файле (`bot_configs.json`)
- Активность пользователей отслеживается (последние 30 минут)
- Сообщения сессий сохраняются для истории

### Безопасность

- Сессии работают только в приватных чатах
- Пользователи видят только тех, кто недавно был активен
- Автоматическая очистка старых данных
- Защита от создания дублирующих сессий

## 🔧 Настройка для разработчиков

### Включение функции

Функция автоматически включается при наличии всех зависимостей:

```python
# В telegram_bot.py
USER_SESSION_AVAILABLE = True  # Автоматически определяется
```

### Конфигурация бота

При создании бота автоматически добавляется `bot_id`:

```json
{
  "bot_id": 1,
  "bot_name": "My Bot",
  "telegram_token": "...",
  // другие настройки
}
```

### Структура данных

#### UserSession
```python
@dataclass
class UserSession:
    session_id: str
    bot_id: int
    initiator: UserInfo
    target: UserInfo
    status: SessionStatus  # PENDING, ACTIVE, REJECTED, ENDED
    created_at: datetime
    message_count: int
```

#### UserInfo
```python
@dataclass
class UserInfo:
    user_id: int
    username: Optional[str]
    first_name: Optional[str]
    last_name: Optional[str]
    display_name: Optional[str]  # Автоматически генерируется
```

## 🐛 Устранение неполадок

### Частые проблемы

**Проблема**: "Нет доступных пользователей для подключения"
**Решение**: Пользователи должны отправить боту хотя бы одно сообщение в течение последних 30 минут

**Проблема**: "Функция подключения к пользователям недоступна"
**Решение**: Проверьте, что все зависимости установлены и система сессий инициализирована

**Проблема**: Сообщения не пересылаются
**Решение**: Убедитесь, что сессия в статусе "active" и оба пользователя находятся в приватном чате с ботом

### Диагностика

Для проверки работы системы используйте тестовый скрипт:

```bash
python test_sessions.py
```
