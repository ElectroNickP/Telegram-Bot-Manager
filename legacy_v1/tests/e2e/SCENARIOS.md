# E2E Test Scenarios

Документация сценариев сквозного (End-to-End) тестирования пользовательского интерфейса Telegram Bot Manager.

## 🔐 1. Аутентификация (Authentication)

### SCENARIO 1.1: Успешный вход в систему
- **Pre-condition**: Приложение запущено, пользователь не авторизован.
- **Steps**:
  1. Открыть страницу `/login`.
  2. Ввести валидный `Username` (admin).
  3. Ввести валидный `Password` (admin).
  4. Нажать кнопку "Sign In" или клавишу Enter.
- **Expected Result**:
  - Редирект на Dashboard (`/`).
  - Отсутствие сообщений об ошибках.
  - В шапке отображается статус пользователя.

### SCENARIO 1.2: Неудачный вход (Неверный пароль)
- **Steps**:
  1. Открыть `/login`.
  2. Ввести валидный `Username`.
  3. Ввести неверный `Password`.
  4. Нажать "Sign In".
- **Expected Result**:
  - Остаемся на странице `/login`.
  - Отображается сообщение об ошибке "Неверные учетные данные".

### SCENARIO 1.3: Выход из системы (Logout)
- **Pre-condition**: Пользователь авторизован.
- **Steps**:
  1. Нажать кнопку "Logout" в навигации.
- **Expected Result**:
  - Редирект на страницу `/login`.
  - Сессия уничтожена (попытка зайти на `/` редиректит на `/login`).

## 📊 2. Дашборд и Управление ботами (Dashboard & Bot Management)

### SCENARIO 2.1: Отображение статуса бота
- **Pre-condition**: Авторизован, создан минимум один бот.
- **Steps**:
  1. Открыть Dashboard (`/`).
  2. Найти карточку бота (например, "D!P$Y").
- **Expected Result**:
  - Карточка содержит имя бота, ID.
  - Индикатор статуса соответствует реальному состоянию (Running - зеленый, Stopped - красный).
  - Кнопки управления (Start/Stop/Edit) доступны.

### SCENARIO 2.2: Остановка бота
- **Pre-condition**: Бот в статусе `Running`.
- **Steps**:
  1. Нажать кнопку "Stop" (квадрат) в карточке бота.
- **Expected Result**:
  - Индикатор статуса меняется на `Stopped` (красный).
  - Кнопка "Start" становится активной, "Stop" - неактивной.
  - В логах появляется запись об остановке.

### SCENARIO 2.3: Запуск бота
- **Pre-condition**: Бот в статусе `Stopped`.
- **Steps**:
  1. Нажать кнопку "Start" (треугольник) в карточке бота.
- **Expected Result**:
  - Индикатор статуса меняется на `Running` (зеленый).
  - Кнопка "Start" становится неактивной, "Stop" - активной.
  - В логах появляется запись о запуске polling/webhook.

### SCENARIO 2.4: Просмотр логов (если доступно в UI)
- **Steps**:
  1. Нажать кнопку "Logs" в карточке бота (если есть).
- **Expected Result**:
  - Открывается модальное окно или страница с логами.
  - Логи актуальны и читаемы.

## 🏪 3. Маркетплейс (Marketplace)

### SCENARIO 3.1: Просмотр каталога
- **Steps**:
  1. Нажать на ссылку "Marketplace" в навигации.
- **Expected Result**:
  - Переход на страницу `/marketplace`.
  - Отображается список доступных ботов/плагинов.
  - Карточка бота содержит: Название, Описание, Рейтинг, Кнопку "Launch/Install".

### SCENARIO 3.2: Поиск/Фильтрация (Search)
- **Steps**:
  1. В поле поиска ввести имя существующего бота.
- **Expected Result**:
  - Список фильтруется, отображается только искомый бот.

## ⚙️ 4. Создание и Редактирование (CRUD)

### SCENARIO 4.1: Создание нового бота
- **Steps**:
  1. Нажать "+ New Bot".
  2. Заполнить форму (Token, API Key, etc.).
  3. Нажать "Create".
- **Expected Result**:
  - Бот появляется в списке.
  - Конфигурация сохраняется на диске.

### SCENARIO 4.2: Валидация токена
- **Steps**:
  1. Ввести некорректный токен в поле "Telegram Token".
  2. Попытаться создать бота.
- **Expected Result**:
  - Сообщение об ошибке валидации.
  - Бот не создается.

### SCENARIO 4.3: Удаление бота
- **Steps**:
  1. Нажать кнопку "Delete" (корзина) у бота.
  2. Подтвердить действие в диалоге.
- **Expected Result**:
  - Бот исчезает из списка.
  - Процесс бота останавливается (если был запущен).

## 📡 5. API (Integration)

### SCENARIO 5.1: Health Check
- **Steps**:
  1. Выполнить GET запрос на `/api/v1/system/health`.
- **Expected Result**:
  - Status 200 OK.
  - JSON ответ с `status: "ok"`.

### SCENARIO 5.2: API Auth
- **Steps**:
  1. Выполнить запрос к защищенному эндпоинту без заголовка Authorization.
- **Expected Result**:
  - Status 401 Unauthorized.

## 🔧 6. Инфраструктура и Устойчивость (Resilience)

### SCENARIO 6.1: Рестарт контейнера
- **Steps**:
  1. Перезапустить Docker контейнер (`docker compose restart`).
- **Expected Result**:
  - Приложение поднимается.
  - Конфигурация ботов сохраняется (благодаря volumes).
  - Боты, которые были в автозапуске, стартуют автоматически.

### SCENARIO 6.2: Обработка некорректного конфига
- **Steps**:
  1. Испортить JSON в файле конфигурации (вручную).
  2. Перезапустить приложение.
- **Expected Result**:
  - Приложение не падает (Graceful degradation).
  - В логах ошибка парсинга.
  - Создается бэкап битого конфига (опционально).
